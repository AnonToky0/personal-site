Git 最容易让人困惑的地方，是同一份代码同时存在于工作区、暂存区、提交历史和远程仓库中。先分清命令改变的是哪一层，再学习命令的组合，日常操作才会有把握。

## 学习目标

学完这组笔记，应该能解释并处理这些问题：

- 为什么文件已经 Add，后来修改的内容却没有进入 Commit？
- 为什么切换分支后，刚写好的文章看起来消失了？
- 为什么工作区干净，仍然可能有提交没有 Push？
- `origin/main`、`main`、`HEAD` 和上游分别指什么？
- 如何导出整个功能分支的差异，而不只是最后一个 Commit？
- 功能写到一半，怎样单独处理另一个 Bug？
- Merge 为什么有时只移动分支，有时创建新提交，有时停在冲突状态？

## 第一阶段：建立状态模型

```text
工作区 --git add--> 暂存区 --git commit--> 本地提交
                                              |
                                           git push
                                              |
                                              v
                                          远程分支
```

这只是主要数据流。分支切换、恢复文件和合并也会改变工作区或暂存区，不能把每条命令理解成单向上传。

完成标准：

- [ ] 能用自己的话说明 Add、Commit、Push 的区别。
- [ ] 能用 `git diff` 与 `git diff --cached` 分别检查两组差异。
- [ ] 知道 `git status` 的 clean 只说明当前文件状态干净。

## 第二阶段：理解引用与远程

完成标准：

- [ ] 能画出两个分支共享祖先、随后分叉的提交图。
- [ ] 能解释 `HEAD -> feature/demo` 与 `origin/feature/demo`。
- [ ] 能区分没有设置上游、没有远程同名分支、没有推送提交。
- [ ] 能选择 `git log '@{u}..HEAD'` 或 `git log HEAD --not --remotes=origin` 回答不同问题。

## 第三阶段：组织任务与协作

完成标准：

- [ ] 恢复 Stash 前先核对记录，知道编号会变化。
- [ ] 能把无关 Bug 放到从正确基线创建的独立分支。
- [ ] 能解决一次 Merge 冲突，或者中止尚未完成的合并。
- [ ] 能说明 Commit、Push、MR / PR、Merge 的区别。
- [ ] 能区分 MR 快进条件与普通 Push 快进检查。
- [ ] 能解释 Rebase 为什么改写提交，以及显式 Lease 能保护什么。
- [ ] 能用父节点核对 Graph，区分界面选中分支、检出分支与上游。
- [ ] 能解释 Build、Test 与 CI 分别验证或执行什么。

## 推荐实践

在独立练习仓库中创建 `lesson.txt`，不要直接拿尚未备份的真实项目做恢复实验。

1. 修改一次，Add 后再修改一次，对照工作区、暂存区与 HEAD。
2. 提交后创建 `feature/demo`，新增文件；切回 `main`，观察文件为何不再出现。
3. 用一个本地 bare 仓库模拟远程，分别观察 Commit 后、Push 后和 Fetch 后的引用位置。
4. 在两个分支中修改同一行并提交，练习 Merge 冲突的检查、解决和中止。
5. 完成一项小任务，用多个有明确意义的提交组织它，再导出相对基线的三点 Diff。
