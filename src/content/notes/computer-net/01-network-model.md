在学习 IPv4、TCP、DNS、代理和 VPN 之前，先建立一张最基本的网络地图：

> 一个程序产生的数据，如何离开本机，穿过一个又一个网络，最终到达另一个程序？

可以先把整个过程抽象成：

```text
你的程序
   ↓
操作系统网络栈
   ↓
网络接口
   ↓
交换机 / Wi-Fi AP
   ↓
路由器 / 默认网关
   ↓
其他网络
   ↓
Internet
   ↓
目标主机上的程序
```

这张图是帮助入门的整体模型，不代表每次通信都一定经过其中所有设备。例如，访问同一局域网里的另一台电脑通常不需要经过默认网关；访问本机的回环地址甚至不会离开电脑。

## 1. Host：主机

**主机（Host）是接入网络并参与网络通信的计算设备。**

例如：

```text
电脑
手机
服务器
NAS
树莓派
工业控制器
```

“主机”描述的是设备在网络中的身份，而不是某一种特定外形。只要设备能够通过网络发送或接收数据，就可以把它看作一台主机。

## 2. Network Interface：网络接口

平时常说：

> 我的电脑 IP 是 `10.4.6.6`。

更准确的说法是：

> 这台电脑的某个网络接口配置了 IP 地址 `10.4.6.6`。

一台主机可以同时拥有多个网络接口，每个接口也可能配置一个或多个 IP 地址：

```text
Windows PC
│
├── Ethernet
│     └── 未连接
│
├── WLAN
│     └── 10.4.6.6
│
├── VPN / TUN
│     └── 10.10.0.2
│
└── Loopback
      └── 127.0.0.1
```

因此不要把一台电脑简单理解成“只有一个 IP”。更准确的关系是：

```text
Host
 └── Network Interface
       └── IP Address
```

当 Ethernet、Wi-Fi、VPN 或虚拟机网络同时存在时，操作系统会根据目标地址和路由规则决定数据从哪个接口发出。

## 3. Adapter：网络适配器

网络适配器（Network Adapter）也常被称为网卡。物理网卡负责与外部传输介质通信，例如：

```text
Ethernet Adapter → 网线
Wi-Fi Adapter    → 无线电波
```

但操作系统里看到的网络适配器不一定对应物理硬件。例如 VPN、TUN、Tailscale 或虚拟机软件都可能创建虚拟适配器。

可以暂时这样区分：

- **Adapter** 更偏向提供网络能力的物理或虚拟设备。
- **Interface** 更偏向操作系统用于收发数据的逻辑接口。

实际工程中这两个词经常混用，现阶段理解其作用比严格区分名称更重要。

程序通常不会直接控制网卡，而是把数据交给操作系统网络栈，再由操作系统选择合适的接口发送：

```text
程序
 ↓
操作系统网络栈
 ↓
网络接口
 ↓
物理网络或虚拟网络
```

## 4. LAN：局域网

LAN 是 **Local Area Network（局域网）**。

同一个家庭、办公室或机房中的电脑、打印机、控制器和服务器，可以组成一个局域网。在同一局域网中，设备通常可以直接通信，不必先进入 Internet。

常见的局域网私有地址看起来像：

```text
192.168.1.x
10.x.x.x
```

但地址长得相似不代表设备一定处于同一个直接相连的网络。例如，不能只凭两个地址都以 `10` 开头，就认定它们属于同一局域网。准确判断还需要结合子网掩码或 CIDR 前缀，这会在下一章展开。

WLAN 是 **Wireless LAN（无线局域网）**。它强调设备通过无线方式接入局域网；LAN 则是更宽泛的网络概念。

## 5. Switch：交换机

交换机（Switch）用于连接同一个局域网中的设备，并把数据转发到正确的方向。

```text
PC-A ─┐
PC-B ─┼── Switch
PC-C ─┘
```

例如 PC-A 和 PC-B 位于同一个局域网时，通信路径可以简化为：

```text
PC-A
 ↓
Switch
 ↓
PC-B
```

这次通信通常不需要经过路由器，更不需要进入 Internet。

交换机具体如何识别设备、为什么会用到 MAC 地址，将在链路层和 ARP 部分继续学习。

## 6. Wi-Fi AP：无线接入点

AP 是 **Access Point（接入点）**。它的主要作用是让无线设备接入局域网：

```text
Laptop
   ))) Wi-Fi
Wi-Fi AP
   ↓
局域网
```

家用“无线路由器”容易让概念混在一起，因为一个盒子通常同时承担多种功能：

```text
Wi-Fi AP
+ Switch
+ Router
+ NAT
+ DHCP
+ Firewall
```

而在公司网络中，这些功能更可能由不同设备分别承担：

```text
Laptop
  ↓ Wi-Fi
AP
  ↓
Switch
  ↓
Router
```

所以，连接 Wi-Fi 时首先接触的是 AP；这个 AP 是否与路由器集成在同一个设备里，要看实际网络结构。

## 7. Router：路由器

路由器（Router）负责在**不同网络之间**转发数据。

```text
Network A
192.168.1.0/24
      │
    Router
      │
Network B
10.0.0.0/24
```

可以先用一句话区分交换机和路由器：

- 交换机主要解决同一局域网内部怎么连接。
- 路由器主要解决不同网络之间怎么到达。

这是入门阶段的简化理解。以后学习 MAC、ARP、VLAN、IP 和路由表后，这个区别会变得更精确。

## 8. Default Gateway：默认网关

假设某个接口的配置是：

```text
IPv4 Address    10.4.6.6
Default Gateway 10.4.0.1
```

其中 `10.4.0.1` 是这个接口使用的默认网关。

可以先这样理解默认网关：

> 当目标不在本地网络中，并且没有更具体的路由可用时，主机把数据交给默认网关，由它继续向其他网络转发。

默认网关通常是同一本地网络中某台路由器的接口，但它不等于 Internet，也不一定直接连接公网。

访问外部地址时，路径可能是：

```text
你的电脑
10.4.6.6
   ↓
默认网关
10.4.0.1
   ↓
其他路由器
   ↓
Internet
   ↓
目标主机
```

因此在网络排障中执行：

```powershell
ping 10.4.0.1
```

是在测试本机是否能够到达默认网关。若成功，至少说明从本机接口到网关之间具备 IP 可达性；若失败，则应优先检查本机配置、无线或网线连接、局域网以及网关状态。

注意：`ping` 使用 ICMP。失败也可能只是设备或防火墙不响应 ICMP，不能单凭一次失败断定网关或网络一定损坏。

## 9. WAN 与 Internet

WAN 是 **Wide Area Network（广域网）**，通常用于连接不同地域或不同局域网：

```text
北京办公室 LAN
       │
      WAN
       │
上海办公室 LAN
```

WAN 不等于 Internet。企业可以建立不对公众开放的专用 WAN。

Internet 也不是一台巨大的路由器或中央服务器，而是大量独立网络互联形成的“网络之网”：

```text
你的 LAN
   ↓
公司网络
   ↓
运营商网络
   ↓
骨干网络
   ↓
另一家运营商或云服务商的网络
   ↓
目标服务器所在网络
```

这也是 Internet 一词的核心含义：**interconnected networks**，即相互连接的网络。

## 10. Client 与 Server：通信角色

Client（客户端）和 Server（服务器）描述的是一次通信中的角色，而不是固定的设备类型。

```text
Client
   │ Request
   ▼
Server
   │ Response
   ▼
Client
```

例如浏览器主动请求网页时，浏览器是客户端，提供网页的程序是服务器。上位机主动请求控制器数据时，上位机也可以是客户端，控制器则是服务器。

同一台电脑可以在不同通信中同时扮演两种角色：

```text
浏览器访问网站       → 作为 Client
本机运行 Web 服务    → 作为 Server
```

真正通信的双方通常是两台主机上的程序，而网络设备负责让数据能够在它们之间到达。

## 11. 一个完整例子

假设 Windows 电脑通过 WLAN 接入公司网络：

```text
你的程序
  │
  ▼
Windows 网络栈
  │
  ▼
WLAN Interface
10.4.6.6
  │
  │ Wi-Fi
  ▼
Wi-Fi AP
  │
  ▼
公司局域网
  │
  ▼
Default Gateway
10.4.0.1
  │
  ▼
其他 Router
  │
  ▼
Internet
  │
  ▼
目标主机上的服务器程序
```

如果：

```powershell
ping 10.4.0.1
```

成功，可以确认本机到默认网关具备 IP 可达性。

如果继续执行：

```powershell
ping 8.8.8.8
```

也成功，则说明 ICMP 数据已经能够经过网关到达更远的外部网络并收到响应。它仍然不能证明 DNS、TCP、TLS 或某个网站一定正常，因为这些属于后续不同的通信环节。

## 12. Loopback：回环

`127.0.0.1` 是 IPv4 回环地址中最常用的一个，主机名 `localhost` 通常会解析到回环地址。

发往回环地址的数据会由操作系统送回本机：

```text
你的程序
 ↓
操作系统网络栈
 ↓
本机上的另一个程序
```

它不需要经过 Wi-Fi、网线、路由器或 Internet。

例如：

```text
127.0.0.1:7890
```

表示访问本机回环地址上的 `7890` 端口。若这是一个代理程序监听的地址，那么浏览器连接到这里时，请求仍未离开电脑；代理程序收到请求后，才会再建立向外的连接。

## 13. 在 Windows 上观察真实网络

### 查看网络适配器

```powershell
Get-NetAdapter
```

重点关注：

```text
Name
InterfaceDescription
Status
MacAddress
LinkSpeed
```

这条命令回答的是：

> 电脑上有哪些网络适配器，它们当前是否连接？

### 查看接口的 IP 配置

```powershell
Get-NetIPConfiguration
```

重点关注：

```text
InterfaceAlias
IPv4Address
IPv4DefaultGateway
DNSServer
```

这条命令回答的是：

> 各个接口当前配置了哪些 IP 地址、默认网关和 DNS 服务器？

也可以使用：

```powershell
ipconfig /all
```

看到一个 IP 地址时，首先问“它配置在哪个接口上”，而不是默认把它当成整台电脑唯一且固定的地址。

## 14. 从近到远建立排障思路

有了整体模型后，排障就可以沿着数据路径逐段进行：

```text
程序
 ↓
操作系统网络栈
 ↓
网络接口是否启用、是否有正确配置？
 ↓
本地网络是否可达？
 ↓
默认网关是否可达？
 ↓
外部 IP 是否可达？
 ↓
目标服务是否正常？
```

当前阶段可以先做以下观察：

```powershell
Get-NetAdapter
Get-NetIPConfiguration
ping 127.0.0.1
ping <默认网关地址>
ping 8.8.8.8
```

每条命令验证的范围不同。后续学习 ICMP、路由、DNS、端口和 TCP 后，还会继续补充这套排障方法。

## 15. 本章核心模型

把设备关系和程序角色合在一起，可以得到：

```text
Client 程序
     │
     ▼
源 Host 的操作系统网络栈
     │
     ▼
Network Interface
     │
     ▼
Local Network / LAN
     │
     ├── Switch
     └── Wi-Fi AP
             │
             ▼
     Router / Default Gateway
             │
             ▼
       其他网络 / WAN
             │
             ▼
          Internet
             │
             ▼
        目标 Host
             │
             ▼
        Server 程序
```

现阶段最重要的不是背定义，而是记住以下关系：

1. 主机通过一个或多个网络接口参与通信。
2. IP 地址配置在网络接口上，一台主机可以同时拥有多个 IP 地址。
3. 交换机和 Wi-Fi AP 帮助设备接入并在本地网络中通信。
4. 路由器连接不同网络；默认网关是没有更具体路线时使用的下一跳。
5. Internet 是许多网络互联形成的网络，不是单一设备。
6. Client 和 Server 是程序在一次通信中的角色。
7. 回环通信只在本机内部进行，不会进入局域网或 Internet。
